# EmbeddedLibrary 总体建设计划

> 计划状态：S2 实现已完成；等待用户手动开启 S3
>
> 规范入口：`docs/ENGINEERING_PROFILE.yaml`、`docs/ARCHITECTURE_STANDARD.md`、
> `docs/CODING_STYLE.md`、`docs/REPOSITORY_WORKFLOW.md`

## 1. 仓库定位

本仓库是会随学习和实际项目逐步积累的嵌入式代码储备库，不以一次性建设完整框架为目标。文件是否进入清单，只表示它是计划存放的生产代码候选，不表示现在必须实现。

建设遵循以下原则：

1. 当前 Profile 和三份规范是唯一标准。
2. 架构行为需要统一时自研；自研没有明显优势时采用成熟库或平台能力。
3. 具体 BSP、Driver、Application 和 Domain 留在实际项目。
4. 新增文件必须有明确用途；“以后可能有用”不足以立项。
5. 同一组件的 `.h` 和 `.c` 放在同一目录，不为了形式拆分 `include/` 和 `src/`。
6. 已有代码可以保留为资产，但不因已经存在就自动成为新项目依赖。

## 2. 推进规则

1. 用户手动开启阶段后，先进行阶段性 Plan。
2. 阶段性 Plan 先决定采用成熟库、平台能力、已有实现还是自研文件。
3. 只有阶段性 Plan 经用户确认后，才创建或修改生产代码和测试代码。
4. 每个组件的 `.h/.c` 作为一个阶段单元；相关简单算法可在一个整理阶段统一处理。
5. 每批完成后同步 `docs/FILE_CATALOG.md`、组件说明和验证证据。
6. 未经用户手动开启，不自动进入下一阶段。
7. 个人工程优先保留高复用、能减少重复代码的组件；项目协议和小型算法不为形式拆分。

状态使用：`现有`、`进行中`、`无`。

## 3. 文件清单

生产代码清单见 [docs/FILE_CATALOG.md](FILE_CATALOG.md)。该清单不记录测试、文档、构建工具和临时产物。

清单中的 `无` 表示目标文件当前尚未创建；目标文件只有在对应阶段确认后才允许出现。成熟库能力记录为能力和采用原则，不预先创建自研包装文件。

## 4. 建设范围

### 4.1 裸机调度

自研最小协作式调度器，负责编译期固定任务表、周期任务、优先级顺序、漏周期处理、执行统计和调用方提供的时间值。

任务通过自身项目端口检查 DMA/外设数据状态；scheduler 不接收 ISR 通知，不建设事件位、任务启停、任务栈、抢占、阻塞、动态任务、任务级同步或 RTOS 模拟。

### 4.2 裸机数据交换

`mizu_fifo` 保持 SPSC 字节暂存语义；调度器只在主循环更新和执行，不引入 ISR 临界区或事件交接机制。具体时间端口、临界区和 RTOS 同步能力按实际项目接入。

### 4.3 控制算法

基础 PID 与串级 PID 作为独立储备阶段。滤波、滑动平均、迟滞、死区和速率限制不建立统一整理阶段，按项目实际重复需求决定。CRC、字节序、IEEE754、COBS 等编码能力优先采用成熟库。

### 4.4 横向 Services

建立 `mizu_status` 状态服务、参数管理、命令管理和菜单。状态服务只接收、保存和查询错误状态，不替调用方执行错误处理；菜单通过参数和命令接口访问项目能力。日志、持久化后端、蓝牙协议栈、显示驱动、字库和渲染优先使用成熟实现或项目能力。

## 5. 阶段路线

### S0：文档重置、文件清单与历史整理 — 已完成

建立本计划和生产文件清单；归档旧组件说明、旧阶段计划、旧资产登记和旧依赖评估文档。本阶段不实现生产代码。

### S1：`scheduler.h/.c` — 已完成

最小裸机协作式调度器。任务配置在编译期固定，运行状态由调用方提供静态槽数组；
调度器只在主循环更新和执行，不处理 ISR、DMA、外部事件或 RTOS 调度。

### S2：`mizu_fifo.h/.c` — 已完成

建设基于参考工程语义的通信字节暂存 FIFO：外部静态存储、双游标、保留一个空槽、
满载拒绝新数据。组件只规定单生产者/单消费者使用约束，不负责平台同步或帧解析。

### S3：`pid.h/.c` — 未开始

独立复核基础 PID 的接口和实现，确认自研或成熟库方案。

### S4：`cascaded_pid.h/.c` — 未开始

独立重写串级 PID，保持与调度和通信解耦。

### S5：`mizu_status.c/.h` — 未开始

统一提供状态类型、错误状态上报、固定存储和查询入口。具体记录、查询、并发和依赖方案在 S5 阶段性 Plan 决定；不承担错误处理回调、恢复或业务数据管理。

### S6：`parameter.c/.h` — 未开始

统一注册项目参数。参数实际所有权留在业务模块，通过 getter/setter 回调访问，不暴露内部变量。

### S7：`command.c/.h` — 未开始

统一命令 ID、静态处理函数绑定、参数边界和执行结果路由，不依赖菜单。

### S8：`menu.c/.h` — 未开始

硬件无关菜单导航、编辑、确认、取消和输入事件状态机；通过 parameter 和 command 使用项目能力。

### 按需阶段 — 不进入固定路线

按实际项目创建通信协议、FreeRTOS、蓝牙、显示、日志、持久化或其他稳定重复的适配契约；具体平台实现不预建。

## 6. 历史资产

不进入新路线的旧生产源码移至 `archive/legacy_src/`，不参与主构建和主线检查；旧说明、旧阶段记录和资产登记继续保存在 `docs/archive/`，历史版本仍可从 Git 查阅。

## 7. 验证与阶段完成

每个开启的阶段必须交付符合当前 Profile 的生产文件、接口说明和与风险相称的验证。通用逻辑按需执行主机测试、Sanitizer、TSan 或 ARM compile-only；目标板、具体 RTOS 和 WCET 未验证边界必须记录。

阶段完成以文件能够被新项目独立采用为准，不要求实现清单中的全部文件。
