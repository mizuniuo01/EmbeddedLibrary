## 1. 仓库定位

本仓库是会随学习和实际项目逐步积累的嵌入式代码储备库，不以一次性建设完整框架为目标。文件是否进入清单，只表示它是计划存放的生产代码候选，不表示现在必须实现。

建设遵循以下原则：

1. 当前 Profile 和三份规范是唯一标准。
2. 架构行为需要统一时自研；自研没有明显优势时采用成熟库或平台能力。
3. 具体 BSP、Driver、Application 和 Domain 留在实际项目。
4. 新增文件必须有明确用途；“以后可能有用”不足以立项。
5. 同一组件的 `.h` 和 `.c` 放在同一目录，不为了形式拆分 `include/` 和 `src/`。
6. 已有代码可以保留为资产，但不因已经存在就自动成为新项目依赖。

## 2. 推进规则

1. 用户手动开启阶段后，先进行阶段性 Plan。
2. 阶段性 Plan 先决定采用成熟库、平台能力、已有实现还是自研文件。
3. 只有阶段性 Plan 经用户确认后，才创建或修改生产代码和测试代码。
4. 每个组件的 `.h/.c` 作为一个阶段单元；相关简单算法可在一个整理阶段统一处理。
5. 每批完成后同步 `docs/FILE_CATALOG.md`、组件说明和验证证据。
6. 未经用户手动开启，不自动进入下一阶段。

状态使用：`现有`、`进行中`、`无`。

## 4. 建设范围

### 4.1 裸机调度

自研最小协作式调度器，负责静态任务表、周期任务、事件任务、固定顺序、有限工作配额、漏周期处理、执行统计、任务启停和时间源注入。

不建设任务栈、抢占、阻塞、动态任务、任务级同步或 RTOS 模拟。

### 4.2 裸机数据交换

复用或重写时间端口、短临界区和字节 FIFO；调度器内部按需使用事件标志或有界计数语义。P3 的 waiter、阻塞队列、复杂事件等待和 mutex 不进入裸机主线。

### 4.3 通信

建立 `frame` 和 `communication` 的通用骨架，表达字节流、FIFO、帧处理、背压、超时和错误边界。`byte_stream` 优先使用成熟库、平台能力或项目传输接口；具体 UART、DMA、蓝牙芯片和协议栈不在本仓库实现。

### 4.4 控制算法

基础 PID 与串级 PID 作为明确储备能力；一阶滤波、滑动平均、迟滞、死区和速率限制统一整理。CRC、字节序、IEEE754、COBS 等编码能力优先采用成熟库。

### 4.5 横向 Services

自研最小错误模型、诊断快照、参数注册表、菜单状态机和静态命令路由。日志、持久化后端、蓝牙协议栈、显示驱动、字库和渲染优先使用成熟实现或项目能力。

## 5. 阶段路线

### S0：文档重置、文件清单与历史整理 — 已完成

建立本计划和生产文件清单；归档旧组件说明、旧阶段计划、旧资产登记和旧依赖评估文档。本阶段不实现生产代码。

### S1：`scheduler.h/.c` — 未开始

最小裸机协作式调度器。

### S2：`byte_fifo.h/.c` — 未开始

按当前规范复核并重写通信 FIFO；先确认成熟实现是否足够。

### S3：`frame.h/.c` — 未开始

建立最小帧处理骨架；具体编码和校验按真实协议选择成熟库。

### S4：`communication.h/.c` — 未开始

组合传输、FIFO 和帧处理，形成非阻塞通信边界。

### S5：`pid.h/.c` — 未开始

复核基础 PID 的接口和实现，确认自研或成熟库方案。

### S6：`cascaded_pid.h/.c` — 未开始

独立重写串级 PID，保持与调度和通信解耦。

### S7：算法整理 — 未开始

统一处理一阶滤波、滑动平均、迟滞、死区和速率限制；每项先判断成熟库是否更合适。

### S8：`error.h/.c` — 未开始

最小错误来源、代码、活动状态和重复计数模型。

### S9：`diagnostic.h/.c` — 未开始

只读诊断快照和 Telemetry 数据边界。

### S10：`parameter.h/.c` — 未开始

静态参数注册表，参数实际所有权仍属于使用它的组件。

### S11：`menu.h/.c` — 未开始

硬件无关菜单导航、编辑、确认、取消和输入事件状态机。

### S12：`command.h/.c` — 未开始

稳定命令 ID、静态处理函数绑定、参数边界和执行结果路由。

### S13：适配契约 — 按需开启

按实际项目创建 FreeRTOS、蓝牙或显示契约头文件；具体平台实现不预建。

## 6. 历史资产

旧 P3 复杂并发实现已从新文件清单中排除，历史内容保存在 `docs/archive/` 和 Git 历史中。它们不作为新主线依赖；是否物理清理生产源码，另行执行明确的维护动作。

## 7. 验证与阶段完成

每个开启的阶段必须交付符合当前 Profile 的生产文件、接口说明和与风险相称的验证。通用逻辑按需执行主机测试、Sanitizer、TSan 或 ARM compile-only；目标板、具体 RTOS 和 WCET 未验证边界必须记录。

阶段完成以文件能够被新项目独立采用为准，不要求实现清单中的全部文件。
