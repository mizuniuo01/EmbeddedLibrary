# EmbeddedLibrary 总体建设计划

> 计划状态：S0 已完成；S1 等待用户手动开启阶段性规划
>
> 规范基线：架构规范 v1.3.0、代码风格规范 v1.2.0、仓库工作流规范 v1.0.0

## 1. 仓库定位

本仓库是长期维护的个人嵌入式 C11 组件库。组件应能够被新项目逐步采用，并保持硬件、板卡、厂商 SDK 和具体业务无关。

建设遵循以下原则：

1. 架构行为需要统一时自研；自研没有明显优势时采用成熟库。
2. 第三方库只在实际需求出现时引入，并记录来源、版本、许可证和适配边界。
3. 具体 BSP、Driver、Application 和 Domain 留在项目仓库。
4. “以后可能有用”不足以立项；新增组件必须有明确场景和近期接入目标。
5. 已有代码属于可复用资产，不代表新项目必须使用，也不要求集中返工。

## 2. 推进规则

1. 只有用户明确指定阶段编号或名称时，才进入该阶段。
2. 阶段开始后先制定阶段性 Plan，冻结 API、所有权、生命周期、错误、资源和测试细节。
3. 阶段性 Plan 经用户确认后才修改生产代码或测试代码。
4. 每批实现后完成本地验证并汇报；需要远端 CI 或硬件验证时单独说明。
5. 阶段收尾必须同步总体计划、组件说明、成熟度和遗留风险。
6. 未经用户手动开启，不自动进入下一阶段。

状态使用：`未开始`、`规划中`、`进行中`、`已完成`、`阻塞`。

## 3. 已有资产定位

完整登记见 [已有资产登记](ASSET_REGISTER.md)。

- P0 的构建、测试、CI、格式和静态分析作为仓库基础设施继续使用。
- P1/P2 的基础容器、编码和控制算法按项目需要复用；不主动扩展能力清单。
- P3 的 `time_port` 和简单临界区可作为裸机主线候选。
- `waiter`、阻塞队列、任务语义 mutex 和复杂 event group 等保留为实验或储备资产，不作为裸机主线依赖。
- 组件被新项目采用前，按实际需求比较现有实现与成熟库。

历史 P0-P3 的阶段设计、提交和 CI 证据继续保存在 `docs/plans/` 与组件文档中，不因路线重置而失效。

## 4. 主线能力边界

### 4.1 最小裸机协作式调度器

自研静态任务表、周期任务、事件任务、固定执行顺序、有限工作配额、漏周期处理、执行统计、任务启停和单调时间注入。不提供任务栈、抢占、阻塞、动态任务或 RTOS 模拟。

### 4.2 裸机数据交换

提供短临界区、可合并事件标志、有界计数通知、字节 FIFO，以及确有需要时的固定事件队列。主要服务 ISR 与主循环之间的数据交换，不提供 waiter、阻塞队列或任务级 mutex。

### 4.3 通信链路

按“项目 Driver → 字节传输端口 → RX/TX FIFO → 帧处理 → 协议与命令”分层。仓库负责非阻塞传输、背压、超时和错误边界；具体 UART/DMA、帧编码和序列化按项目选择。

### 4.4 错误、诊断、日志与 Telemetry

自研最小错误状态和诊断快照，统一来源、代码、活动状态和重复计数。Telemetry 读取只读诊断快照；日志优先使用成熟库并通过 sink 接入。产品降级、停机和恢复策略由项目决定。

### 4.5 参数与持久化

自研最小静态参数注册表，提供稳定 ID、类型、范围、权限和读写绑定；参数仍由实际组件拥有。持久化通过语义化 Repository 接口完成，具体 Flash、EEPROM、NVS、磨损均衡和掉电一致性由平台或成熟库负责。

### 4.6 菜单与显示

自研硬件无关菜单状态机，负责层级、导航、编辑、确认、取消和输入事件。具体页面属于项目；显示 Driver、字体和渲染优先采用成熟实现。菜单状态更新和显示传输分别调度。

### 4.7 命令、蓝牙与接入

提供最小静态命令路由，完成稳定命令 ID 查找、参数边界检查和结果返回。权限、运行模式和业务动作由项目决定。蓝牙使用厂商或成熟协议栈，只作为通信、命令和诊断的一种适配方式。

### 4.8 可选健康监督

健康监督独立于调度器，根据调度统计和任务打点输出健康状态及是否允许喂狗。硬件喂狗、复位和安全策略由项目决定。

## 5. 阶段路线

### S0：计划重置与资产登记 — 已完成

停止旧 R0 全仓库依赖评估路线，建立新总体路线与资产分类。未修改生产代码、测试或构建。

### S1：最小裸机协作式调度器 — 未开始

实现周期/事件任务、执行顺序、工作配额、漏周期和统计。阶段性 Plan 需先冻结时间语义、任务表、回调和过载边界。

### S2：裸机数据交换 — 未开始

复核并按需调整现有 FIFO、临界区和通知能力，形成适合 ISR/主循环的最小数据交换集合。

### S3：字节传输与非阻塞通信 — 未开始

定义字节传输端口、RX/TX 数据流、背压、超时和错误传播；使用主机替身验证，不实现具体 UART Driver。

### S4：错误、诊断与 Telemetry — 未开始

实现最小错误状态、诊断快照和可替换输出边界；按实际需求评估成熟日志库。

### S5：参数与 Repository — 未开始

实现静态参数注册和访问控制，定义语义化设置 Repository；持久化后端由项目或成熟库提供。

### S6：菜单状态机与显示模型 — 未开始

实现硬件无关菜单导航和编辑，通过参数服务访问可调参数，并提供独立显示模型或 sink。

### S7：命令路由与接入示例 — 未开始

实现最小命令路由，并以串口或蓝牙示例展示通信、参数、诊断和菜单的组合。

### S8：任务健康与看门狗监督 — 可选、未开始

只有实际项目需要时开启，保持与最小调度器分离。

### S9：后续储备 — 按需开启

安全输出、低功耗、Bootloader、固件升级、DMA/cache、多核和真实 FreeRTOS 适配均由实际项目触发独立规划。

## 6. RTOS 与第三方库策略

FreeRTOS 项目直接使用原生 queue、notification、event group、mutex 和 semaphore。算法、协议、菜单、参数和诊断保持 RTOS 无关；项目自行决定任务划分、优先级、栈、队列和阻塞关系。

第三方依赖采用前必须记录上游来源、锁定版本、许可证、内存和线程要求、目标 MCU 适用性、适配边界、验证平台及升级方式。协议栈、序列化、日志、显示渲染、Flash 管理和 RTOS 同步默认优先考虑成熟实现。

## 7. 测试与完成标准

每个阶段必须交付可独立接入的能力、公共接口、组件说明和适用测试。通用逻辑执行 GCC/Clang 主机验证；涉及内存安全、未定义行为或并发时分别运行 Sanitizer/TSan；嵌入式兼容性通过 ARM compile-only 检查，目标板、RTOS 和 WCET 未验证边界必须明确记录。

简单适配和转发层不重复编写低价值测试。阶段完成以能够被新项目采用为准，不以实现所有可能功能为目标。
