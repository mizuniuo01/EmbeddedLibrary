# 已有资产登记

本文件记录路线重置前已经完成的代码。分类只决定后续规划地位，不改变现有代码、测试和历史成熟度。

## 基础设施

| 资产 | 当前用途 | 后续处理 |
| --- | --- | --- |
| CMake、CTest、Presets | 主机和交叉编译入口 | 继续维护 |
| GCC/Clang、Sanitizer、TSan | 代码与并发验证 | 按组件风险使用 |
| clang-format、Clang-Tidy、Cppcheck | 风格和静态检查 | 继续维护 |
| GitHub Actions | 远端验证 | 阶段完成时使用 |

## 按需复用组件

| 组件组 | 现有组件 | 定位 |
| --- | --- | --- |
| 基础契约 | `foundation_status`、`tick32`、`numeric` | 新组件可直接复用，修改时保持稳定语义 |
| 数据容器 | `byte_fifo`、`fixed_queue`、`object_pool`、`snapshot_buffer` | 项目需要时比较现有实现和成熟库 |
| 编码与校验 | `crc`、`byte_order`、`ieee754_byte_order`、`cobs` | 仅在具体协议需要时采用 |
| 控制算法 | `pid`、`cascaded_pid`、各类滤波与限制器 | 保留现有成果，不主动扩展算法清单 |
| 裸机基础候选 | `time_port`、`critical_section` | S1/S2 阶段复核后决定是否直接使用 |

## 实验与储备组件

| 组件 | 原用途 | 当前定位 |
| --- | --- | --- |
| `waiter` | 统一阻塞等待者状态 | 不进入裸机主线 |
| `queue_port` | 带 waiter 的阻塞队列 | 裸机主线只复用确有需要的非阻塞语义 |
| `event_group` | 事件位等待和广播 | S2 只评估简单事件标志需求 |
| `count_notification` | 带等待的计数通知 | S2 只评估非阻塞有界计数需求 |
| `mutex_port` | 跨执行上下文互斥 | RTOS 项目优先使用原生 mutex |

## 使用规则

1. 现有组件不会因路线重置被删除。
2. 组件不因已经实现而自动成为新项目依赖。
3. 主线阶段需要某项资产时，先检查其语义是否符合该阶段的最小需求。
4. 自研实现没有明显优势时，在对应阶段评估成熟库或平台原生能力。
5. 复核只针对即将使用的组件，不再进行全仓库逐项依赖调查。
