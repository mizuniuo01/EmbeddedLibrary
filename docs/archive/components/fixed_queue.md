# fixed_queue

固定元素大小、固定容量的值复制队列，不覆盖未出队元素。

## 公共边界

所属层级：Libraries；唯一组件依赖为 `foundation_status`，使用标准 C11。
实例由调用方以 `{0}` 初始化并提供静态存储，字段仅供实现使用；实例初始化后禁止按值复制。
所有传入指针必须指向存活对象，所报长度不得超过真实对象大小。C 无法检测悬空指针或虚报容量。
存储和输出区不得与实例、内部存储或同次其他输出重叠；重叠检查在任何复制之前完成。
失败不写普通输出，不改变有效数据；只有明确的饱和诊断计数可在容量不足时改变。
成功重新初始化会清空逻辑内容及统计，失败保持旧绑定；实例及存储均由调用方拥有，不释放内存。

同一实例的全部 API（包括查询）必须由调用方串行化。不同实例使用不重叠存储时可重入。
没有内置锁、等待、超时、回调或任务创建，不保证直接用于 ISR/任务并发；
P3 才实现 RTOS 同步适配。主机测试不替代目标 MCU 原子性、WCET、DMA/cache 或上板验证。

内存区间检查是明确的 ABI 边界：依赖目标提供 `uintptr_t`，对象地址转换后保序，
字节地址差对应对象内字节距离。当前验证目标为 Linux GCC/Clang 和 ARM GCC 的平坦地址 ABI。
不适用于未经验证的分段地址或特殊指针平台；不依赖主机字节序。
内存函数采用标准 C11，长度及不重叠已预检；仅相应调用局部抑制 Annex K 建议，
不要求可选 `memcpy_s/memset_s`，不关闭全局分析规则。

## 接口与失败行为

- `init(queue, storage, storage_size, element_size, capacity)`：元素大小和数量必须非零。
  先检查乘法溢出（OVERFLOW），再检查字节容量（BUFFER_TOO_SMALL），不默默截断容量。
  静态数组可用 sizeof(array) / sizeof(array[0]) 推导元素数量；指针不能这样推导。
- 内部使用字节区和 memcpy，不要求存储区对齐。输入输出对象仍需满足调用方自身类型的要求。
- `push/pop`：单个元素；满/空分别 FULL/EMPTY。
- `push_some/pop_some`：以元素数为单位复制能处理的完整元素，部分成功返回 OK 和数量。
  非零请求无进展返回 FULL/EMPTY 且数量不变；零请求允许 NULL 并返回 OK 和零。
  请求数量乘元素大小溢出时返回 OVERFLOW。
- `peek` 空队列返回 EMPTY；`peek_at` 的索引相对队头，从零开始，index >= size 返回 OUT_OF_RANGE。
- 所有读写方向均拒绝与队列存储或实例重叠；包含数量输出与数据区域的重叠。
- `size/capacity/free/rejected_count/high_water_mark` 返回状态码及 size_t。
  每个无法完整接受的合法入队请求累计一次拒绝计数（包括部分成功），SIZE_MAX 饱和；
  high-water mark 单位为元素，非法参数不增加统计。

复制的是对象表示，不执行析构或深拷贝。若元素包含指针，队列复制指针值；
它不会延长所指对象寿命，不可把临时栈对象指针交给延后消费的队列。
拥有外部资源的元素在丢弃或重新初始化前由调用方逐个出队并清理。

## 资源与验证

RAM 为 sizeof(fixed_queue_t) + capacity × element_size；栈 O(1)。
复制复杂度 O(实际元素数 × element_size)，查询及索引计算 O(1)。
主机覆盖未对齐字节区、元素乘法溢出、容量不足、逻辑索引、环形回绕、批量部分传输、
重叠拒绝、失败原子性和统计饱和。目标临界区时间依赖元素大小与批量数，需项目测量。
证据见 [P1 阶段计划](../plans/P1_FOUNDATION.md)。
